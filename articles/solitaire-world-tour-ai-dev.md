本業の合間と週末だけで、スマートフォン向けのカードゲーム『ソリティア世界旅行』を作り、2026 年 9 月に iOS と Android で公開しました。作り始めてから公開まで 4 か月です。

クロンダイク・ソリティアを 1 ゲーム解くたびにコインが貯まり、貯めたコインで航空券を買って次の街へ飛んでいくゲームです。盤面の背景はいま滞在している街の水彩画で、日本と韓国の 34 の街を巡ります。1 ゲームごとに、その街の豆知識がひとつ手に入ります。

![富士山を背景にしたクロンダイクの盤面](/images/solitaire-world-tour/board.jpg =300x)

コードは AI が書き、画像はすべて画像生成で作り、豆知識も AI で調べて作りました。この記事では、個人が本業の合間にこの量を作り切るために組んだ仕組みを書きます。

1. 豆知識 340 項目(日英 680 本)を、ルビ付き・出典付きで作る仕組み
2. 34 都市の背景と絵葉書を作る仕組み
3. Unity Editor の操作を AI に任せる仕組み
4. Android のクローズドテストの通し方

## 何に AI を使い、何を人がやったか

最初に全部書いておきます。

| 作ったもの | AI がやったこと | 人がやったこと |
|---|---|---|
| コード | Claude Code が書いた | 仕様を決める・動作を確かめる |
| 画像(街の背景・絵葉書・キャラクター) | OpenAI の画像生成(gpt-image-2)ですべて生成 | 採用する絵を選ぶ |
| 豆知識 | 調査と執筆 | レビューして直す |
| 効果音 | 使っていない | 本物のトランプを擦るなどして録音 |

Claude Code は remote-control の機能を使い、外出先からも実装を進められるようにしていました。本業の合間の細切れの時間を使えたのは、これが大きかったです。

## 1. 豆知識 340 項目を作る仕組み

### 1 都市に 1 エージェント

豆知識は 1 都市 10 個、34 都市で 340 個あり、日本語と英語の両方を用意しています。これを 1 つの AI エージェントにまとめて書かせると、後半の都市ほど質が落ちました。そこで、**1 都市につき 1 エージェントを立ち上げ、並列で書かせる**形にしました。

各エージェントには、同じ依頼テンプレートと制作仕様を渡します。制作仕様には次のような決まりを書いています。

- 1 都市につき日本語 10 個 + 英語 10 個
- 各項目に タイトル / カテゴリ / 本文 / 出典 URL の 4 つを必ず入れる
- カテゴリは 歴史 / 文化 / グルメ / 自然 / 現代 / 地理 の 6 つのうち、10 個全体で 3 つ以上に分ける
- 出典は信頼できる順に 公式サイト > 自治体・省庁 > 主要メディア > 学術機関 > 専門メディア > Wikipedia
- 日本語は です・ます調で、小学校高学年でも読める言葉にする。本文はルビ記法を除いて 150 字以内

出典は原稿に残しますが、アプリの画面には出しません。書いた内容を後から人が確かめるための記録です。

### 原稿は Markdown、ルビは青空文庫式

原稿は都市ごとの Markdown ファイルです。難読語と固有名詞には、青空文庫式のルビ記法 `｜親文字《よみ》` で読み仮名を付けます。

```text
｜新宿駅《しんじゅくえき》は1日に約300万人が使う、ギネス世界記録にも認定された「世界でいちばん利用者の多い駅」です。
```

読みが不確かな語にはルビを付けず、ひらがなにするか言い換えます。誤った読みを出すより安全だからです。アプリ側では、この記法を読み取って漢字の真上に読み仮名を表示しています。

### Markdown を正本にして、JSON は生成する

アプリが読むのは JSON ですが、手で書き換えるのは Markdown だけにしています。JSON はスクリプトで作ります。

```bash
python3 tools/build_trivia_json.py {slug}   # md → JSON を生成
python3 tools/build_trivia_json.py --check  # 書き込まずに md と JSON の差分を確認
python3 tools/lint_trivia_ja.py {slug}      # 日本語のルビ記法と文の数を機械でチェック
```

### 日本語と英語は必ず同じ回で直す

一度、日本語の豆知識を全体的に短く書き直したことがあります(本文を約 25% 削り、タイトルは 330 件中 325 件を変更)。このとき英語を後回しにしたため、英語 330 件が古い日本語の訳のまま取り残されました。チェック用のスクリプトは日本語専用で、英語の取り残しには気づけません。

それ以来、制作仕様に「日本語版と英語版は必ず同じ回で書き換える」「英語は日本語に書かれている事実だけを訳す。英語にだけ情報を足さない」と書いています。

## 2. 34 都市の背景と絵葉書を作る仕組み

背景と絵葉書も、Claude Code のスキルとして手順をまとめました。1 都市ずつ、次の順で進みます。

1. その都市の象徴的なランドマークや街並みを調べ、資料をまとめる
2. 資料をもとに、水彩画の画風を決めたプロンプトで背景を生成する
3. 背景と同じモチーフを切り取った構図で、絵葉書を生成する
4. 生成した画像を Unity のプロジェクトへ取り込み、その都市を遊べる状態にする

絵葉書は、背景に描かれた象徴的なモチーフを切り取ったものにしています。「滞在した街の景色の一部を持ち帰った」と感じてもらうためです。

![集めた絵葉書とスタンプを見返す旅路の画面](/images/solitaire-world-tour/journey.jpg =300x)

## 3. Unity Editor の操作を AI に任せる

Unity のゲームを AI に書かせると、コードを書いたあとの「コンパイルが通るか」「画面がどう見えるか」を確かめる手間が残ります。ここを AI が自分で確かめられるよう、Editor を外から操作する MCP を 2 つ入れました。

- **MCP for Unity**(UnityMCP): シーンや GameObject、アセットの操作、Editor の中での C# の実行
- **uloop**: コンパイル、コンソールのログの取得、テストの実行、Game View のスクリーンショット、Play Mode での入力の再現

これで AI は、コードを書いたあとに自分でコンパイルし、エラーを読み、Play Mode でボタンを押し、スクリーンショットを見て、見た目のずれを直す、というところまで進められます。

UI は、Prefab を使わず、uGUI をコードで組み立てています。画面の構成がすべてコードにあるので、AI が読んで直しやすいからです。

プロジェクト直下の `CLAUDE.md` には、「Editor が起動しているときは、これらの MCP を自分から使うこと」「Library/ や Temp/ などの生成物は読まないこと」「大きな YAML やシーンファイルは丸ごと読まず、必要な項目だけを取り出すスクリプトを書くこと」といった決まりを書いています。AI が同じことを毎回聞かなくて済むようにするためです。

## 4. Android のクローズドテストの通し方

個人の開発者アカウントで Android アプリを公開するには、製品版の前にクローズドテストが要ります。条件は、**12 人以上のテスターが、直近 14 日間続けてオプトインしていること**です。10 年ほど前に Android アプリを出したときには無かった仕組みです。

テスターを集めるときにやったことは次のとおりです。

- Google グループを作り、誰でも参加をリクエストできるようにする
- 日本語の Discord「Androidクローズドテスト攻略組」、英語の Testers Community、Reddit のテスター募集のサブレディット、X で募集する。相互テストが前提の場では、自分もほかの人のアプリをテストする
- 友人や知人の Android ユーザーにも直接頼む
- 途中で抜ける人に備えて、12 人より多めに集める
- テスターには「14 日間アンインストールしない」「初日に 1 ゲーム最後まで遊ぶ」「気づいたことを 1 行でも書いてほしい」と伝える
- 14 日の間に、小さな更新を何度か出す

14 日が終わると、製品版へのアクセスを申請します。申請フォームでは、テストの様子、ゲームの対象ユーザー、テストを受けて何を直したかなどを聞かれるので、見つかった不具合や端末名、出した更新を具体的に書きました。

製品版の審査は 3 日ほどで終わると思っていましたが、実際には半月ほどかかりました。そのため iOS 版を先に 9 月 19 日に公開し、Android 版は 9 月 28 日の公開になりました。Android も同じ日に出したい場合は、かなり早めに動き始めることをおすすめします。

## いちばん難しかったのは、数字を決めること

仕組みを整えても、AI に任せきれなかったのがゲームの数字です。1 回クリアしてどれくらいコインがもらえるか、次の街はどれくらい離れていて、航空券はいくらにするか。この釣り合いで旅の進み方がまるで変わるので、ここがいちばん大変でした。

航空券の値段は、街と街の距離(緯度経度から求めた距離)に、距離の帯ごとの単価を掛けて決めています。遠い街ほど高くなり、上限はありません。
